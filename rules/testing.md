# 测试硬约束（core 中立层）

Red-Green-Refactor 节奏由 TDD 技能/工作流驱动，本规则管测试怎么写。语言中立纪律在此；测试框架、断言库、Mock 设施与并发编排原语以当前栈 rules（如 testing-java、testing-python）为准。

## 结构与命名

- Given-When-Then 三段式，空行或注释分隔；一个测试断言一个行为；多组数据用参数化测试（设施以当前栈 rules 为准）。
- 测试类/文件 = 被测单元名 + 测试后缀（后缀约定以当前栈 rules 为准）；方法/函数 = `被测名_场景_期望结果`；辅助方法 given/when/then 前缀。
- 测试独立：无顺序依赖、无共享可变夹具，每个测试自构造 fixture。
- 断言有意义行为（返回值/状态变化/副作用），不断言中间变量或日志；异常断言用当前栈推荐的异常断言设施。

## 隔离与分层

- 单元测试不碰真实外部资源：DB/HTTP/文件系统/MQ 一律 Mock；只 Mock 直接依赖，禁止用部分 Mock 跳过被测单元自身逻辑。
- 单元测试不启动应用容器/框架上下文；集成测试分层放置，数据库与容器设施按项目既有测试约定（以当前栈 rules 为准）。
- 交互验证只验证关键交互，不过度验证内部实现细节。

## 覆盖策略

- 优先级：P0 核心业务规则（金额/状态流转/转换）→ P1 边界与异常（null/空集合/0/负数/精度/越界/并发竞态/外部失败）→ P2 分支覆盖；P3 不测 getter/setter/纯数据载体/琐碎实现。
- 边界检查清单（每个方法过一遍）：null/空字符串/空集合/单元素/超大集合；0/负数/最大值/精度丢失（十进制类型 vs 浮点）；初始/终态/非法状态转换；跨天/跨月/跨年/闰年/时区；并发写入/重复提交/竞态；外部超时/5xx/不可用。
- 零装饰测试：禁无断言、禁只测 happy path、禁凑覆盖率；核心分支必须有失败路径测试。试金石：若被测函数全部返回空、测试仍能通过，该测试必须丢弃重写。
- Bug 修复先写复现测试（Red）再修，只补 1 个回归用例锁定该缺陷不复发；新功能才按 P0→P1→P2 完整覆盖；重构前先建特征测试（characterization test）保护网。
- 并发竞态用语言同步原语编排（原语以当前栈 rules 为准），禁止 sleep。
