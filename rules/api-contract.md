# API 契约硬约束（core 中立层）

接口设计基线在此；框架级校验注解、统一响应类名与事件发布设施以当前栈 rules 为准。项目已有统一响应封装时以项目既有结构为准，不另造第二套。

## 统一响应与分层
- 接入层统一响应封装：`{success: boolean, code: string, message: string, data: T}`（项目既有封装结构优先）；禁止直接返回原始异常堆栈或裸持久化实体。
- 接入层只做参数校验（边界完成）、权限拦截、响应封装，不写业务逻辑。
- 前端双层解析：传输层成功标志 → `resp.data` 业务体 → 业务校验标志（如 `passed`）；错误提示用 `resp.message`，禁止直接读顶层业务字段。
- 敏感数据返回前端自动脱敏；危险操作（覆盖生产/批量删除/切换已上线对象）前置校验拦截+确认机制，不允许裸接口；写接口防重提交。

## SSE 实时日志
- 服务端必须在业务终态主动收口（事务提交/持久化之后关闭 emitter），禁止依赖超时自动断开；SSE 超时只是兜底不是收口机制。
- 收口点：批次终态/手动 stop/完成事件（事务提交后回调）；先关单对象通道再判批次；前端收到终态事件后主动关闭 EventSource。

## 契约要素
- REST：路径/方法/入参结构（含校验规则）/出参结构/错误码语义齐全；内部签名给接口文档级前置/后置/幂等/线程安全声明。
- 批量/长耗时接口必设计：进度查询方式、可中断语义、部分失败的结果表达。
- 外部交互：协议/超时/重试（仅幂等）/失败降级契约；接口权限与数据权限双层校验。
