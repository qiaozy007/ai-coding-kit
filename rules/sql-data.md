# SQL 与数据硬约束（core 中立层）

数据访问基线在此；ORM 批处理陷阱、数据库连接串方言开关、存量库 DDL 自动更新陷阱以当前栈 rules（如 sql-data-java）为准。

## 查询与索引
- SQL 一律参数绑定（占位符/预编译语句），动态表名列名白名单；禁 `SELECT *`、无界全表扫描；结果集评估规模上限。
- 禁 N+1：循环单条查库改批量查询（IN/JOIN/批处理）；深度 OFFSET 改 keyset 分页（`WHERE id > :lastId ORDER BY id LIMIT n`）。
- 核心查询/筛选/关联字段必建索引；警惕隐式类型转换/函数包裹导致索引失效（方言级陷阱见当前栈 rules）。

## 写入与批处理
- 更新/删除必须校验影响行数，防静默失败（改 0 行却返回成功）；核心写操作幂等设计（幂等键/唯一约束兜底）。
- 批量写入用驱动层批量提交设施（设施与 ORM 陷阱以当前栈 rules 为准）；超大规模分批提交防事务日志膨胀。
- 大批量流式读取（fetchSize/游标）+ 分批写入，禁止全量入内存。

## DDL 与模型
- 存量库 DDL 自动更新（schema auto-update）添加 NOT NULL 列必须指定 DEFAULT 或等价兼容策略（方言陷阱见当前栈 rules），否则启动失败。
- 表设计基线：逻辑删除统一；创建/更新时间与创建人/更新人齐全；枚举状态字段注释齐全（每个取值业务含义明确）。
- 持久化模型不出数据访问边界，跨层用 DTO/Projection，避免懒加载序列化泄漏。
- 数据归属与生命周期明确：谁写入/谁更新/谁归档/是否可重入（迁移/比对类任务必问）。
