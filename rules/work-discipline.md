# AI 协作工作纪律

通用约定，萃取自已验证的 data-diff 项目 AGENTS.md 与 pms 项目 work-discipline；与具体工作流（spec-kit/Superpowers 或自定义）无关，任何任务均适用。

## 提问/执行边界

- 用户以提问、咨询、评审、故障排查口吻发起（为什么、怎么办、能不能、应该如何、评审、分析、看看、帮我判断……）时，先输出【方案 + 具体改动清单（文件路径 · 改动预览 · 影响面 · 待裁决点）】供 review；仅在用户回复授权指令（开始/执行/同意/按 X 做/改一下/实现/动手/去做/继续……）后才动手编辑文件。
- 语义模糊时，以「用户是否已明确授权动手改文件」为准；未授权一律先方案。

## 执行纪律

- 执行期不打断：方案/计划已被用户明确确认（或直接执行指令）后，按既定顺序连续推进，每阶段做真实验证（编译/测试/回归）后直接进入下一项；禁止中途停下来等用户点「继续」。
- 任务状态全绿才可回写勾选；既有红测如实登记归属，不夹带修复。
- 文件名禁止内嵌日期做版本，版本交给 git；搬迁一律 `git mv` 保历史。
- 跨会话交接：长任务跨会话时，会话结束前须把交接三件套（已完成/进行中/下一步 + 验证证据）回写 `docs/changes/<变更名>/tasks.md` 备注或 `implementation.md`；新会话按 INDEX → changes 产物接管；无变更目录时落项目可用的记忆机制（若有）。

## Credits 节约

- 模式分级：只读咨询（问原因/评审/看日志）用 Ask 模式；明确改代码才用 Agent 模式；小改动不派子代理/Quest。
- 探索预算制：只读取与本次修改直接相关的文件（目标文件+直接依赖），禁止无目标全仓遍历；信息不足先向用户要指定文件/字段，不自行翻项目猜。
- 最小改动：编辑只改必要片段，对话不整文件全量复制；禁止「顺便」追加需求外的优化/校验/异常包装。
- 输出精简：不科普基础概念、不逐行翻译日志、不复述已知背景；解释性文字最短，优先结论+关键改动点。
- 会话策略：同一任务在同一会话继续；任务切换/话题跑偏坚决新开会话，不跨任务复用长上下文。
- 大日志本地先行：先用现成脚本/日志分析技能本地聚合，只把结构化摘要交给 AI 归因，禁止整目录日志进上下文。
- 链路裁剪：按变更大小裁剪工作流与评审强度；代码审查只在核心逻辑变更/合并前跑一次；不满意先改 prompt，不反复 regenerate（每次都是新计费请求）。

## 命令输出捕获

- PowerShell 下把含中文的命令输出（git/mvn/python 等）捕获进变量做比对或解析前，必须先置 `[Console]::OutputEncoding=UTF8`，否则 PS 5.1 按 ANSI 解码产生乱码假阳性；直接显示不受影响。
- 点目录（如 `.qoder/`）不被 glob 类搜索工具匹配时，列文件清单用 PowerShell `Get-ChildItem -Force` 且显式 `Write-Output` 输出（`Select-Object` 管道输出可能被吞成空结果）。
